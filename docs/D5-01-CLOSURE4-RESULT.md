## 2. 产品缺陷（不是测量误差）与最小修复

### 2.1 机制（一句话）

原生视图是挂在窗口之上的 `WebContentsView`，位置来自 domain 意图
`bounds.y + TITLE_BAR_H + BROWSER_CHROME_H`（= 外壳顶 + 90pt 固定 chrome）；
而 `browser-notices` / `browser-error` 是 chrome **之下**的 flex 条带 ——
两者必然重叠，DOM 在原生视图下面 → **提示条被网页整个盖住、点击也进不了外壳**。

上一轮（Closure-4 追加取证）用白底页面判"非绿 = 提示可见"，这个判据分不开"白底网页"和"提示条"，
所以当时无法定论；本轮改成**整页纯绿**的稳定场景后一次判定成立。

### 2.2 最小修复（让网页让位）

| 文件 | 改动 |
| --- | --- |
| `src/browser/BrowserApp.tsx` | 每次渲染后用 `useLayoutEffect` 量一次「chrome 之下、网页之上」的 DOM 条带高度：``.web-viewport` 顶 − `.browser-shell` 顶 − BROWSER_CHROME_H`，经 `onViewportReserve(windowId, reserve)` 上送（值不变不触发重渲染，无回路） |
| `src/desktop/useDesktop.ts` | 存一份 `viewportReserves`（windowId → pt），传进 `manager.nativeIntents(state, hostSize, viewportReserves)` |
| `src/main.tsx` | 把回调接到浏览器窗口 |
| `electron/window-manager.cjs` | `nativeIntents(state, host, reserves = {})`：浏览器窗口的原生视口 = `bounds.y + TITLE_BAR_H + BROWSER_CHROME_H + reserve`，高度同减；**默认 `{}` → 既有几何逐字不变**，非浏览器窗口与未上报窗口一律 0 |
| `electron/window-manager.d.cts` / `window-domain.d.cts` | 补类型声明（`reserves` 形参；`BROWSER_CHROME_H` 的默认导出，运行时本来就有） |
| `tests/window-manager.test.mjs` | 新增用例：让位公式、未上报/非浏览器窗口不受影响、负值/NaN/超大值不产出负高度与小数 |

**没有做的事**（边界声明）：没有新增缩放入口、没有改浏览器执行契约（lease/claim/verify 未动）、
没有新增 IPC 通道或桥键、没有放宽任何安全面冻结断言。

### 3.1 坐标计算与验收证据相互独立（不是自证）

* **坐标计算**用三条**实测**通道的几何：① 像素（`screencapture -l <CGWindowID>` 扫行/列得原生视图矩形）；② DOM 预留矩形（`.web-viewport` + 窗口内容原点 = `window.screenX/screenY + 标题栏`）；③ 真实指针反推（点一个已知屏幕点 → **网页自己回报** client 坐标 → 反推视图原点）。
* **验收证据**来自与坐标计算无关的四个来源：外壳自己记录到 `isTrusted` 点击（命中哪个按钮）、
  网页自己记录到的指针事件数与 `clientX/Y`、截图像素颜色、以及窗口/网页的真实状态变化。
* 因此"算出来的坐标"与"证明点击到了"是两套东西：**没有一条断言只证明计算与自身一致**。
* 安全闸（每次真实点击前重新校验）：本实例窗口存活 → 最前面的 layer-0 窗口属于**本进程** → 本进程是
  **活跃 App**（NSWorkspace）→ 落点在本窗口内容区内；任一不满足就**不发点击**（宁可不点，绝不碰用户
  正在用的另一个 OpenArc 实例）。另加"热身"：系统偶尔会吃掉"刚被激活的窗口的第一下点击"，
  先点窗口标题栏确认外壳真的收到 pointerdown，之后每条点击断言都以"外壳/网页收到"为准，
  而不是以"我们发了点击"为准。

## 7. 上一轮口径更正

1. **VIS-GEOMETRY-1** 仍是"测量误差"（domain 意图 = 像素真值），但当时那句**"原生视图没有错位、提示不需要让位"是错的**：
   原生视图确实按意图摆放，可是**意图本身没有把 DOM 提示条算进去**，于是提示条被盖住 —— 这是产品缺陷，
   已在本轮修复。
2. Closure-4 的聚焦探针 `notice-coverage-probe.mjs` 已删除：它的判据（白底页上"非绿 = 提示可见"）
   分不开白底网页与提示条；本轮用整页纯绿场景 + 双侧事件重做，结论以本报告为准。
3. "真实按键未改变页面缩放"更正为：真实按键**会**让页面进入缩放态（实测 `dpr 2 → 2.4`），
   但该状态仍**不属** D5-01 必需项。
