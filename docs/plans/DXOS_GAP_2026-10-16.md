# OpenArc × DX OS 对齐盘点（2026-10-16）

> 依据：DX OS 0.5.1 逆向报告（30 个内置应用注册表）、`dxos-port/r1` 分支（`~/.openarc-worktrees/dxos-port-r1`，最新 `0b70a60`）的 `docs/dxos-port/Dx-*-RESULT.md`、当前 `integration/ui-core` 工作区（桌面 `OpenArc OS.app` 就是它构建的）。只读盘点，未改任何后端代码。

## 0. 一句话结论

**DX OS 的后端能力基本都已经移植了，但在另一条分支上；现在最大的缺口不是"还缺什么功能"，而是三条线没合流。**

| 线 | 在哪 | 内容 | 状态 |
|---|---|---|---|
| A · 后端移植 | `dxos-port/r1`（独立 worktree） | 84 个提交、507 个文件、约 14 万行：协议引擎、Agent/任务、Skill、MCP 工具调用、自动化、媒体（渲染/短剧/抠图/音乐库/图片声明）、虚拟文件树、平台诊断、开发者平台、应用市场、第三方集成插件；配套 React 界面（Skill 中心、任务控制台、模型协议页、MCP 工具开关、组织控制台） | 已提交；全量测试 2747 条（8 条为机器负载抖动，单独复跑通过）；**未合进 ui-core** |
| B · 新前端（Vue 壳层） | `integration/ui-core` 工作区 | 本轮的 macOS 27 界面、21 个应用窗口、应用程序弹窗、设置重排等 | **全部未提交**；桌面 app 用的就是它 |
| C · Codex 设计对齐 | `~/.codex/worktrees/ui-design-alignment`（游离 HEAD） | 另一个工具在做 UI 对齐；10-15 晚有改动直接写进了 ui-core 工作区 | 与 B 共用工作区，有互相覆盖风险 |

后果：B 线的几个应用为了"能用"，在前端或 ui-core 里各自做了一份**简化实现**（Skill 存成 SKILL.md、自动化在渲染进程里定时、天气 / 视频导出 / 图片声明各写了一个小服务），而 A 线已经有更完整、带权限审计的后端版本。合流后这些要换成 A 线的域。

## 3. 建议顺序

1. **先收口（半天量级，必须先做）**：把 ui-core 上的 Vue 改动按「外观 / 应用 / 后端小服务」分批提交；和 Codex 那条线约定谁改哪些文件；再把 `dxos-port/r1` 合并进 `integration/ui-core`。预计冲突集中在 `electron/main.cjs`、`electron/preload.cjs`、`src/styles.css`、`src/main.tsx`。
2. **Vue 接 A 线的域，并下线 B 线的重复实现**：Skill、自动化、天气、视频剪辑、图片声明、音乐、应用市场、MCP 工具开关、模型协议页、组织治理权限策略。
3. **补 Vue 新页面**：短剧工坊、开发者工作台、第三方集成入口（领星 / 紫鸟 / 钉钉 / 夸克 / Figma / Illustrator）、相册 AI 操作、画布素材库、对话的流式与审批。
4. **真实环境联调**：至少接一个文本模型 + 一个生图模型的 Key 跑通对话、Skill、短剧、自动化；机器内存压力大（A 线报告记录 swap 用了 24 GB / 25 GB），联调前先清理后台进程。
5. **二期**：局域网协作服务、英文界面、Windows、窗口标签合并。

## 4. 需要你拍板

1. 合并方向：以 ui-core（Vue 前端）为主、把 r1 合进来，对吗？r1 的 React 页面合并后只做参考、逐页迁 Vue。
2. 天气、视频剪辑、图片声明各有两份实现：统一用 A 线后端（建议），还是保留 B 线的？
3. 任务双表是否合并；core 任务是否要在控制台可操作（A 线遗留的两个产品问题）。
4. 局域网多人协作首版要不要。
5. 第三方集成（领星 / 紫鸟 / 钉钉 / 夸克）是否真要；不要的话前端就不做入口。
