## 一、主进程内导航的执行边界（§二）

**契约裁决：保留 in-process execution class，但不容许任何"新分类绕过旧约束"。** 受控浏览器导航的 Domain 是 main 进程内的原生 \`WebContentsView\`，out-of-process executor 结构上无法执行它；本轮不把它硬搬进子进程，而是把**缺失的证明补齐**，并逐条明确"哪些能证明未执行、哪些只能判不可知"：

1. **claim 前撤权或停止 → 不派发**：审批等待期间经治理入口撤掉 ai 的工具权限 → 调用在 claim 前被拒（\`SIDE_EFFECT_AUTHORIZATION_REVOKED\`）、**0 导航**、页面零变化、0 ACTIVE lease（真实门禁 P1；单测 B1）。
2. **派发后停止 → 不是"未执行"**：真实派发后用户取消任务 → 调用收敛为 **UNKNOWN_EFFECT**（不是 FAILED、更不是"未执行"），Task/Step 都有终态，且**没有第二次派发**（P2；单测 B2）。
3. **超时后迟到完成 → 不覆盖权威状态**：\`/late\` 页面在超时之后才落地 —— 页面确实落到了目标地址，但调用**仍是 UNKNOWN_EFFECT**、即时只读恢复结论是 **INDETERMINATE（无结论）**、站点只收到 1 次请求（P2.5–P2.7；单测 B3 还证明"显式只读恢复"才允许收敛，且 §28 下 Task 仍保持 BLOCKED）。
4. **执行中关闭标签 → 不可知 + 不转向**：派发后关掉该标签 → 调用 UNKNOWN_EFFECT、Step/Task 终态一致、**没有**对其它标签/管理界面的新导航（P3；单测 B4）。
5. **结果核查归因**：新增**派发追踪**——每次受控导航记一条 dispatch，其中 \`loadURL()\` 自身 promise 的结果是"这次调用引发的加载"的因果证据；只有"我们请求的地址被提交过"才算我们的提交，别人的导航单记 \`foreignCommit\`。因此**地址恰好等于目标也不算本次成功**（P4：本次导航在途时用户自己导航走 → 调用判"未生效/不可知"，绝不记成 SUCCEEDED；单测 B5 覆盖"证据显示被中止 → 不得认领成功"）。
6. **并发与重复**：双击批准只产生 1 次派发、1 个 lease（P5）；两次导航各自绑定各自的地址与 plan，互不串号（P6；单测 B6 还覆盖"并发同一执行记录只派发一次"与"批准后 plan 被改 → 旧批准立即失效、0 派发"）。
7. **plan 完整性加固**：批准时留存的 \`expectedEffects\` **独立副本**与当前 plan 逐字比对（不一致 → PLAN_STALE）；执行入参 url 必须与 plan 自己的效果副本自洽（不一致 → PRECONDITION_CHANGED）。这是"旧批准不能用于新目标/新地址"的机械保证。

**如实声明的限制（in-process ≠ out-of-process）**：
- 没有独立 executor 的进程寿命证据（没有 child exit / socket lifetime）；
- 派发证据是**内存账本**（有界 64 条），进程重启即消失 → 冷启动后任何"是否发生"的追问只能判 INDETERMINATE；
- "能证明未执行"的必要条件很窄：这次加载被中止 **且** 我们请求的地址从未提交 **且** 当前地址不是目标；其余一律不可知（绝不猜成功、也不猜没发生）。

证据：\`tests/d5-01-browser-inprocess-boundary.test.mjs\` **6/6**；\`node experiments/d5-01/browser-inprocess-boundary-e2e.mjs\`（真实原生视图 + 本地站点 + 产品 UI）**32/32 PASS**（1 NOT VERIFIED = 像素级可见性交给下面的可见性门禁）。

## 二、本任务窗口的真实可见性（§三）

**仪器**：\`screencapture -x -o -l <CGWindowID>\`（窗口自身画面）+ \`cliclick\`（CGEvent **真实指针**）+ Quartz 读像素。**只按本进程 PID 定位窗口**，每次点击前重新校验"我们仍是最前面的窗口 + 落点在本窗口内容区内"，否则宁可不点（绝不碰另一个实例）。

**实测证据**（工作区运行 19/20 PASS）：
- 网页**真的可见**：视口中心像素是页面纯绿，且窗口左边缘对照列**无绿**（排除"外壳背景是绿的"这一误判）；
- 网页**真的可交互**：真实指针点进页面，页面自己记录到点击坐标（标定后命中按钮本体，误差 ≤6px，目标 = CLICK-ME）；
- **标签栏**：真实指针"新建标签"真的多出一个标签、点第二个标签真的切换；操作前后两帧像素不同；
- **地址栏**：真实指针点击后焦点真的进入输入框；
- **面板让位**：下载面板打开时视口中心像素不再是页面绿、关闭后回到页面绿；
- **窗口缩放**：缩放后重新标定坐标，真实指针点击仍然命中（误差 ≤8px），截图尺寸随之变化（连续多帧落盘）。

**OPEN 发现（如实登记，不冒充通过）—— VIS-GEOMETRY-1**：
像素测量与点击标定两个**互相独立**的仪器都显示：网页那一块（原生视图）在屏幕上的位置比 DOM 预留位置**偏高约 83–103pt**、高度也更大（436pt vs 预留 322pt），而真实指针点标签栏/地址栏却仍然生效。两者未能完全对上，**未定位根因**，因此可见性这一项**不判完成**，V4c 一项保持 FAIL。
（干净导出树上该门禁复跑了 7/9 + 1 NOT VERIFIED：那一轮我们的窗口没能成为最前面的窗口，安全闸按设计拒绝发真实点击 → 指针项保持 NOT VERIFIED，而不是冒险点击。这一波动也如实登记。）

## 三、D4-03D 文件级超时（§四）

- **根因（确定性复现，不是猜测）**：测试夹具里 \`server.close(cb)\` 在还有**未结束请求**的连接时**永不回调**（最小复现：2.5s 仍未关闭；\`closeAllConnections()\` 之后立即关闭）。夹具用它做清理 → 测试文件进程挂死，表现为 **0 断言失败**、文件级 180s 超时、每次命中**不同**文件（甚至纯单测文件）、整轮约 930s 才结束。
- **最小修复（测试仪器）**：统一 \`closeServer()\`（\`closeIdleConnections\` + \`closeAllConnections\` + 有界兜底），落在 \`tests/model-fake-provider.mjs\`（共享）、\`tests/fixtures/d4-04-provider.mjs\`、\`experiments/d5-01/site.mjs\`、\`tests/tool-d4-03d-closure.test.mjs\`。**没有删测试、没有跳过文件、没有提高超时**。
- **基线对照**：同一条命令在改动前的 \`0094e17\` 导出树上**同样复现**（43 tests / 42 pass / **0 fail** / 1 文件级超时 / exit 1）—— 预先存在，不是上一轮引入。
- **修复后**：工作区连续 2 次 \`npm run test:d4-03d\` = **52/52 PASS，exit 0**；干净导出树再跑 1 次 = **52/52 PASS，exit 0**。
